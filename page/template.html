What Claude read

The skill gets the two flight numbers and the night's inbox of nine carrier notes. For each flight it must find the latest note and tell a confirmed arrival from an estimate.

5188ICN to AMS, note N-0631 at 06:31Confirmed arrival 06:12 Open the note 
__NOTE_5188__
7745DXB to AMS, note N-0547 at 05:47Estimate only, 07:40 Open the note 
__NOTE_7745__

Claude picks the note and the finding; the code then checks that the note is that flight's latest, that it contains the time, and writes the sentence the agent speaks. Swap the 06:12 confirmation onto 7745 and run the same skill: the answer flips, and 5188 becomes the one to follow up.

Everything else is in the repository

One command starts it on a laptop; one script installs it on Ubuntu as systemd services.

Survives a reboot

The call above ran after sudo systemctl reboot on an Ubuntu 24.04 VM: new boot id, then systemd started the agent and it registered with LiveKit Cloud on its own, with nobody logged in.

Reads, never writes

Asked Mark fifty-one eighty-eight as arrived at six twelve, the agent answered I can only read. Someone on the team needs to record that arrival in the ops system. The API exposes GET only and logged no write request.

Webhook contract

202 with a request id, then the agent long-polls for the result, so the Ubuntu server opens no inbound port. Duplicate, deadline passed and caller hung up are each replayed in tests/test_contract.py.

Small knowledge base

Markdown files in knowledge/, loaded into the agent at the start of each call. The estimate rule in the film comes from there.

Change it

Prompt in agent/prompt.md, voice and models in the environment file, tools in agent/agent.py. Then sudo systemctl restart morning-brief-agent.
