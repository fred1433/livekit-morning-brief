The skill gets the two flight numbers and the night's inbox of nine carrier notes. For each flight it must find the latest note and tell a confirmed arrival from an estimate.

Claude picks the note and the finding; the code then checks that the note is that flight's latest, that it contains the time without denying it, and writes the sentence the agent is told to read out. In the film the voice rephrases it slightly; the flight numbers and times are the ones the code wrote. Swap the 06:12 confirmation onto 7745 and run the same skill: the answer flips, and 5188 becomes the one to follow up.

Survives a reboot

The call above ran after sudo systemctl reboot on an Ubuntu 24.04 VM: new boot id, then systemd started the agent and it registered with LiveKit Cloud on its own, with nobody logged in. The agent's journal ties the call to that boot. The Claude webhook ran on another machine, standing in for the team's Claude setup.

Reads, never writes

Asked Mark fifty-one eighty-eight as arrived at six twelve, the agent answered I can only read. Someone on the team needs to record that arrival in the ops system. The API has no write route; the agent has no write tool.

Webhook contract

202 with a request id, then the agent long-polls for the result, so the Ubuntu server opens no inbound port. Duplicate, deadline passed, retry, failure and caller hung up are each replayed in tests/test_contract.py.

Small knowledge base

Markdown files in knowledge/, loaded into the agent at the start of each call. The estimate rule in the film comes from there.

Change it

Prompt in agent/prompt.md, voice and models in the environment file, tools in agent/agent.py. Then sudo systemctl restart 'morning-brief-*'.
